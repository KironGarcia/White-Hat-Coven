===== Block A — How EAS gets the files (no GitHub required) =====

There is '''no''' GitHub remote for this game. That is fine. EAS does **not** clone GitHub.

What it does:

1. From the PC, ''eas-cli'' packs the WHC project and uploads it to Expo cloud.
2. If the folder is a **git repo**, the pack follows **git**. Files that were never ''git add'' (status ''??'') **do not go up**.
3. No ''git commit'' and no ''git push'' are required. '''Tracked or newly staged files''' are enough.
4. Dev Client on the phone is Metro from the PC. The cloud APK is **not** Metro. A file that “plays in Dev Client” can still be missing on EAS if it is untracked.

'''Do not''' tell Kiron he must create a GitHub repo to ship testers. '''Do''' ''git add'' every new asset the JS ''require()''s (audio, icon, sprites).

===== Block B — Failure 1: EAS Maven cache dead (not our Gradle) =====

Log (first wave):

{{{code
Error resolving plugin [id: 'expo-autolinking-settings']
Could not find kotlin-gradle-plugin-api-1.9.24.jar
Searched in:
http://maven.production.caches.eas-build.internal/artifactory/libs-release/.../kotlin-gradle-plugin-api-1.9.24.jar
}}}

or ''Read timed out'' on the same host.

* That URL is **Expo’s internal Maven proxy**, not WHC, not Kotlin version we chose.
* Expo status '''2026-09-03''': incident '''Elevated Android builds rate'''. Text: maintenance on the cache that serves Maven artifacts to Android builds made the cache **unavailable**. Identified ~08:39 PDT, marked resolved ~09:06 PDT.
* A later build at ~11:30 local still failed: “resolved” on the status page ≠ every worker healthy. The error string is still the cache, not ''GameScreen''.
* A circular ''import type'' in ''constants.ts'' (''DEV_FORCA_FASE'' ← ''progressao-fases'') was a real code smell and was fixed with an inline ''1 | 2 | 3 | 4''. It is **not** what prints ''kotlin-gradle-plugin-api''. Do not blame that import for this Gradle line.

===== Block C — Failure 2: workaround caused Maven Central 429 =====

Someone (this session) put in ''eas.json'' ''preview.env'':

* ''EAS_BUILD_DISABLE_MAVEN_CACHE=1''
* ''GRADLE_USER_HOME=/tmp/gradle-home''

That **did** skip the dead cache. Gradle then hit public Maven. Log (build that had those env vars — they showed in “Project environment variables”):

{{{code
Error resolving plugin [id: 'com.facebook.react.settings']
Could not GET 'https://repo.maven.apache.org/maven2/.../gson-2.9.1.pom'
Received status code 429: Too Many Requests
}}}

Everyone bypassing the Expo cache at once got rate-limited. '''Current ''eas.json'' must have no those env vars''' (reverted). Do **not** put them back unless the internal cache is down **and** Maven Central is healthy.

===== Block D — Failure 3: Metro missing pirate-coin audio (our tree) =====

After Gradle passed far enough to bundle JS:

{{{code
Unable to resolve module ../../assets/audios/moeda-pirata.ogg
from WHC/src/systems/audio-jogo.ts
None of these files exist:
  * moeda-pirata.ogg
  * assets/audios/moeda-pirata.ogg
}}}

Cause:

* JS ''require('../../assets/audios/moeda-pirata.ogg')'' plus plugin copy ''moeda-pirata.ogg'' → ''whc_moeda_pirata_v1.ogg'' in ''plugins/with-audios-android.js''.
* On disk during the failed upload the file was **absent** (folder had Coin, hihihi, etc., no ''moeda-pirata.ogg''). Dev Client can look like it “has audio” from an older Metro cache; EAS is a clean pack.
* Even after copying the file, it must be '''git add'''ed or EAS will still not see it.

Fix before the next APK:

1. File exists: ''WHC/assets/audios/moeda-pirata.ogg'' (real pirate SFX if Kiron has it; a copy of another ogg is only a last-resort placeholder).
2. ''git add WHC/assets/audios/moeda-pirata.ogg'' (and any other new assets).
3. Confirm ''ls WHC/assets/audios/moeda-pirata.ogg'' locally **then** run EAS.

''expo doctor'' also warned: ''assets/icon.png'' is '''970×860''' (not square). That did **not** stop the build (doctor exit 1, then prebuild continued). Optional later: square icon. Not the Gradle/Maven crash.

===== Block F — Dev flags: tester APK vs recording =====

In ''src/constants.ts'':

| Flag | Tester APK | Recording / Dev Client |
|---|---|---|
| ''DEV_FORCA_FASE'' | '''null''' | ''4'' only to test phase 4 |
| ''DEV_BOSS_CAPITAO_ALTITUDE'' | '''null''' | ''10'' only to spawn Capitão at 10 m |
| ''DEV_RESET_FLAGS_CONHECIDAS'' | '''false''' | ''true'' once so Phishing-Man is first-contact (orb mode) |

'''At the time this checkpoint was written, ''DEV_RESET_FLAGS_CONHECIDAS'' was still ''true''.''' That wipes known-URL encantos on every app start. Testers would always see first-contact aviso. Set '''false''' before the official tester APK.

''App.tsx'': if ''DEV_BOSS_CAPITAO_ALTITUDE !== null'', invasion is forced to ''capitao_pirata''. Keep altitude '''null''' for testers.
